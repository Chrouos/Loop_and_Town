# Relationship Map｜灰潮鎮人物關係

人物關係不是背景設定，而是 Event Graph 的輸入條件。

```text
當前 Loop 的信任 / 壓力 / 尊重 / 義務
→ 改變角色選擇
→ 改變 Schedule
→ 改變 Event Variant
→ 延遲影響其他角色
```

重要 Canon：

> Relationship State 只屬於當前 Loop。Reset 後 NPC 不保留上一輪關係與記憶。

主角可以記得曾經建立過的關係，但 NPC 不會因為「residue」逐輪記起來。

---

# Relationship State

不要使用單一 `friendship = 70`。

目前通用維度：

```text
trust       願不願意相信主角提供的資訊
closeness   當前 Loop 的相處深度
respect     是否感到自己的選擇權被尊重
pressure    是否感到被秘密、預知或情緒壓迫
```

故事需要時可增加局部 state，例如：

```text
availability
obligation
fear
exposure
promise_pressure
```

但它們都必須有具體敘事意義。

禁止作為一般 NPC Relationship State：

```text
residue
memory_residue
previous_loop_memory
```

不能出現：

```text
yuan.residue >= 3
→ 記起上一輪 17:58 的電話
```

如果主角下一輪知道 17:58 的電話，來源應是主角自己上一輪的 Perception / Captured Memory，而不是予安記得。

# 主角 ↔ 林知夏

## 表面

姊妹。

## 真正關係

知夏一直支持妹妹離開灰潮鎮、去都市念大學。

主角從小就想去外面的世界看看，她真正想離開的是小鎮尺度，不是家人。

兩人的裂痕不是來自主角「選擇離開」，而是知夏在主角真正離開前突然改變態度。

```text
知夏支持妹妹去都市
→ 知夏在 Soft Rewrite 中看見主角留在灰潮鎮並於 18:31 死亡
→ 開始干涉返鄉、搭車與停留安排
→ 故意說出最能把妹妹推遠的話
→ 姊妹爆發人生中最嚴重的爭吵
→ 主角去都市念大學
→ 兩人沒有真正和好
→ 知夏死亡
```

主角真正的遺憾不是：

> 我不應該離開。

而是：

> 為什麼我們最後一次好好說話，是那麼久以前？

這條關係也定義知夏的重要倫理滑坡：

```text
支持別人的選擇
→ 知道太多結果
→ 相信自己知道什麼才對別人最好
→ 替別人做選擇
```

這條關係主要影響主角後期選擇，而不是一個簡單 Trust meter。

知夏作為上一代特殊記憶持有者，屬於 Story Canon exception，不是普通 Relationship State。

# 主角 ↔ 周予安

## 過去

兩人從小認識。

知夏與予安本身就是朋友，主角年紀較小時常跟在兩人旁邊；長大之後，主角與予安才逐漸形成真正屬於兩人的朋友關係。

兩人曾經互相喜歡過，但從未正式交往。

比較接近：

> 如果再多一點時間，也許會發生什麼。

主角一直想去都市，最後真的考上外地大學。

予安也曾經想離開灰潮鎮，甚至考上外地學校，但因母親生病、家庭照顧與父親的鐘錶店，一次又一次把離開延後。

所以兩人的真正對照不是：

> 妳想走，我想留下。

而是：

```text
主角：一直想走，而且真的走了
予安：一直以為自己之後會走
```

## 五年前的車站

主角與知夏大吵後，原本答應送她去車站的予安收到：

> 不用了。

予安最後還是去了，但只看到火車離站。

主角不知道他曾經去過。

因此五年後主角回到灰潮鎮，予安真的站在出口接她，對他而言有一層沒有說出口的意義：

> 五年前沒接到的人，這一次終於接到了。

## 當前核心衝突

主角知道予安一直沒有真正離開。

但她一開始容易把這理解成「他選擇留下」。

實際上予安自己也不確定，那些年到底有多少是選擇、多少只是一次又一次的延後。

予安則可能羨慕主角真的做到了自己當年沒有做到的事。

這使兩人的關係成為整個故事「離開 / 留下 / 誰替誰決定」的重要鏡像。

## 當前 Loop State

建議使用：

```text
trust
closeness
respect
pressure
availability
```

`availability` 表示玩家是否正在佔用他原本的人生行程，例如房仲約、鐘錶店工作。

Reset 後這些回到當輪基準。

### Cross-loop asymmetry

Loop A 即使主角與予安建立很深的信任：

```text
主角 → 記得
予安 → Loop B 不記得
```

所以真正的情感成本是：

> 主角記得一個「更了解自己的予安」，但下一輪的予安還沒有和她共同經歷那些事。

這也是主角必須學會尊重的界線：

> 我知道上一輪的你怎麼選，不代表這一輪的你已經做出同樣選擇。

# 林知夏 ↔ 周予安

兩人從小就是朋友。

知夏也是少數知道予安其實曾想離開灰潮鎮的人。

她曾經提醒他：

> 你不是只有留下這個選項。

五年前知夏死亡當天，17:58 打給予安。

當時予安正在和父親爭吵，第一次真正說出：

> 我從來沒說我要這間店。

他看到知夏來電，但只想著晚一點再回。

18:31，知夏死亡。

這讓予安把兩件原本不應該相等的事綁在一起：

```text
替自己的人生說話
≈
自私 / 可能傷害別人
```

因此他五年後更習慣優先處理別人的需要。

這條關係是予安 Arc 的重要來源之一，但不是跨 Loop 記憶機制。

---

# 林知夏 ↔ 許若晴

近似非血緣姊妹，但知夏不是把若晴當成需要「送出灰潮鎮」的人。

知夏真正支持的是若晴認真看待自己的攝影與選擇。

高中時，知夏第一次看穿若晴的照片不只是「好看」，而是在記錄正在消失與改變的東西。

她問若晴：

> 妳為什麼都拍快要沒有的東西？

也曾提醒她：

> 不要先替自己決定「我只能留在這裡」。

五年前若晴曾拿到外地攝影課程錄取，卻最後沒有去，也沒有告訴知夏。

若晴真正的遺憾不是「沒有完成知夏希望她離開的願望」，而是：

> 我一直沒有真正回答她問我的問題。

因此如果主角拿知夏作為壓力：

```text
「知夏一定希望妳走」
→ pressure +1
→ respect -1
```

如果主角承認答案應該由若晴自己決定：

```text
「我不知道知夏會希望妳怎麼選」
→ respect +1
→ 可能增加 trust
```

這條關係直接服務整個故事的核心：理解一個人，不等於能替她選。

# 許若晴 ↔ 周予安

若晴高中時就常待在鐘錶店。

鐘錶店對她來說不是約會場所，而是一個：

> 可以待著，而且不需要解釋為什麼待在這裡的地方。

予安通常不追問她是不是又和家裡發生什麼，只會告訴她後面有椅子、冰箱有茶。

若晴年少時確實對予安有過好感。

現在則更接近長期安全感。

她把予安與鐘錶店都視為灰潮鎮裡「不會突然消失的東西」。

因此知道予安正在考慮賣店時，若晴受到的衝擊不只是朋友可能離開，而是：

> 原來我也一直把別人當成不會改變的背景。

若晴遇到壓力時，仍可能先聯絡予安，而不是主角：

```text
wakaharu.trust low
+ wakaharu.pressure high
→ 若晴找予安
→ 予安 Schedule 改寫
→ 玩家失去 / 延遲另一條調查線
```

這是同一 Loop 內的 delayed consequence，不是跨 Loop 關係累積。

# 主角 ↔ 許若晴

兩人五年前並不熟。

主角離開灰潮鎮時，若晴年紀還小。

若晴認識主角的方式是：

> 知夏姊那個很會讀書、後來真的去了都市的妹妹。

主角則只知道若晴是：

> 姊姊以前照顧過、很會拍照的女孩。

所以兩人的真正關係是在現在的 Loop 裡建立。

若晴某種程度羨慕主角真的走出了灰潮鎮，但不代表她想複製主角的人生。

如果主角一直把「離開」當成替若晴解決問題的方法，若晴可以明確反擊：

> 妳一直問我為什麼不走。
> 可是妳有沒有想過，我可能真的喜歡這裡？

這是主角很重要的 Character Moment。

它提醒主角：

```text
我的人生答案
≠
別人的人生答案
```

Relationship State 上，若晴對主角特別重視 `respect`。

主角越使用跨 Loop 知識替她安排生活，可能越有效率，卻同時增加 `pressure` 並降低 `respect`。

反之，主角如果提供資訊但把最終決定留給若晴，未必得到最快的結果，卻可能建立更穩定的 trust。

# 林知夏 ↔ 葉庭安

過去是調查搭檔。

核心決裂：

```text
知夏：只要繼續試，就可能找到所有人活下來的線
庭安：每一次試驗都是真實的人在承擔結果
```

庭安仍在履行知夏要求她保密的承諾，所以她對主角隱瞞不等於敵對。

局部 State 可使用：

```text
trust
exposure
promise_pressure
```

例如：

```text
exposure high
+ trust low
→ 庭安提前獨自行動
```

# 葉庭安 ↔ 陳柏勳

兩人五年前都藏過資料。

```text
共同秘密
→ 互相保護
→ 互相猜忌
```

如果其中一人的秘密被公開，另一人的 Schedule 也會變化。

這是 Event Graph 應呈現的角色因果，不應只寫成數值變化。

---

# 陳柏勳 ↔ 周志遠

核心是鏡像：

```text
柏勳藏醫療紀錄
志遠藏證物
```

兩人都認為對方不該替別人決定真相，卻都曾經以「保護」為名做過類似選擇。

---

# Relationship effect 必須改變行為

任何關係條件都必須能回答：

```text
誰受到影響
→ 為什麼
→ 改變哪個決定
→ Schedule 哪一段因此不同
→ 哪個 Event Variant 被打開 / 關閉
```

Example：

```text
wakaharu.trust >= 2
AND wakaharu.pressure <= 1
→ 17:20 主動說出要去車站

reporter.exposure >= 2
AND reporter.trust < 0
→ 提前進研究所
```

不要只有：

```text
trust +1
→ 台詞比較友善
```

若數值完全不影響人物決策，就不屬於核心 Relationship System。

---

# Player Knowledge 與 Relationship 必須分離

玩家跨 Loop 保存的是主角側資訊：

```text
Captured Memory
Investigation Wall
主角自己的經歷
```

NPC 關係狀態則 Reset。

因此玩家可能知道：

> 上一輪這樣說會讓予安生氣。

但這一輪仍必須重新建立情境，不能把上一輪的 Trust 直接帶過來。

---

# 設計原則

1. NPC 有自己的人生與 Schedule，不是 clue dispenser。
2. 玩家只能影響資訊與情境，不能直接控制角色最終選擇。
3. Relationship State 是當輪狀態，不是永久好感度。
4. 普通 NPC 不存在跨 Loop memory residue。
5. 主角可以利用跨 Loop 的人物理解，但系統不能自動替玩家判斷「誰在說謊」。
6. 所有跨 Loop 的可檢索資訊必須遵守 Perception Boundary / Memory Capture 規則。
