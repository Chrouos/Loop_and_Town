# Relationship Map｜灰潮鎮人物關係

人物關係不是背景設定，而是 Event Graph 的輸入條件。

```text
情感／信任／愧疚／承諾
→ 改變角色選擇
→ 改變 Schedule
→ 改變 Event Variant
→ 延遲影響其他角色
```

---

# 核心關係圖

```text
                         林知夏
                    ┌─────┼─────┐
                    │     │     │
                 主角   若晴   庭安
                  │      │      │
                予安─────┘      柏勳
                  │               │
                  └───────────志遠
```

這張圖只代表「有高影響關係」，不代表單純好感。

---

# 主角 ↔ 林知夏

## 表面

姊妹。

## 真正關係

```text
依賴
→ 主角想獨立
→ 知夏開始控制
→ 主角離開
→ 死亡前半年疏遠
→ 主角留下愧疚
```

## Event 影響

主角越執著於「救姊姊」，越容易忽略其他角色的代價。
這條關係主要影響後期 Ending Choice，而不是早期 Trust 數值。

---

# 主角 ↔ 周予安

## 表面

高中同學、老朋友。

## 深層

予安知道主角離開灰潮鎮之後的人生。
主角則知道予安一直沒有真正離開。

這讓兩人的衝突不是「你為什麼不相信我」，而是：

> 妳每次都想走，我每次都留下。

## Runtime 指標

```text
trust
residue
availability
```

- `trust`：予安願不願意配合玩家做不合理的調查
- `residue`：他保留前一輪記憶的程度
- `availability`：玩家是否正在佔用他原本的人生行程

---

# 林知夏 ↔ 許若晴

## 關係

近似非血緣姊妹。

知夏對若晴最大的影響不是舊案，而是曾經認真支持她離開灰潮鎮。

因此若晴現在的核心矛盾是：

```text
想離開
vs
留下照顧母親
vs
覺得自己辜負知夏
```

## Runtime 影響

如果玩家只拿知夏壓若晴：

```text
pressure +1
trust -1
```

如果玩家先理解若晴自己的選擇：

```text
trust +1
agency +1
```

這兩種方式都可能讓若晴提供情報，但後續行為不同。

---

# 許若晴 ↔ 周予安

## 過去

若晴年少時對予安有好感。

## 現在

更接近依賴一個熟悉、安全、不會突然離開的人。

予安則把她當妹妹。

## Event 影響

若晴遇到壓力時，可能先聯絡予安而不是玩家。

所以：

```text
玩家對若晴 trust 不足
+ 若晴壓力過高
→ 若晴改找予安
→ 予安 Schedule 被改寫
→ 玩家失去另一條調查線
```

# 林知夏 ↔ 葉庭安

## 過去

調查搭檔。

## 決裂核心

```text
知夏：只要繼續試，就可能找到所有人活下來的線
庭安：每一次試驗都是真實的人在承擔結果
```

## 現在

庭安仍在履行知夏要求她保密的承諾。

所以她對主角說謊，不等於她敵對主角。

## Runtime 指標

```text
trust
exposure
promise_pressure
```

當 `exposure` 高、`trust` 低時，她會提前獨自行動。

---

# 葉庭安 ↔ 陳柏勳

兩人五年前都藏過資料。

不是戀愛，也不是共謀。
而是互相知道「對方也做過不能公開的選擇」。

```text
共同秘密
→ 互相保護
→ 互相猜忌
```

如果其中一人的秘密被玩家公開，另一人的 Schedule 也應改變。

---

# 陳柏勳 ↔ 周志遠

核心是鏡像關係。

```text
柏勳藏醫療紀錄
志遠藏證物
```

兩人都認為對方不該替別人決定真相。
兩人也都做了同樣的事。

這條關係適合用來讓玩家理解主題：

> 「保護」有時候只是比較好聽的控制。

---

# 關係狀態設計

不使用單一 `friendship = 70` 解決全部問題。

至少拆成：

```text
trust       願不願意相信你
pressure    目前被逼迫程度
obligation  覺得自己欠對方多少
fear        對目前事件的恐懼
residue     輪迴記憶殘留
```

Event 不應直接問「好感夠不夠」，而要問更具體的條件。

例如：

```text
wakaharu.trust >= 2
AND wakaharu.pressure <= 1
→ 17:20 主動說出要去車站

reporter.exposure >= 2
AND reporter.trust < 0
→ 提前進研究所

yuan.residue >= 3
→ 記起上一輪 17:58 的聲音
```

---

# 設計原則

任何 Relationship effect 都必須能回答：

```text
誰改變了誰
→ 為什麼
→ 改變了哪個決定
→ Schedule 哪一段因此不同
→ 哪個 Event Variant 被打開
```

如果關係數值只改台詞，沒有改行為，就不是核心關係系統。
