# Chapter 2｜活下來的人

這章的功能不是讓玩家「救成功」，而是第一次證明：

> 改變死者，不等於改變事件。

---

# 玩家進入這一輪時知道什麼

上一輪已知：

```text
17:40 柏勳離院
18:05 柏勳與若晴碰面
18:31 若晴死亡
```

玩家最自然的實驗是：

> 不讓若晴去舊車站。

---

# 讓若晴改變行程的方法

玩家不能直接按「阻止若晴」。

必須先理解她為什麼會去。

若晴前往車站有三個原因：

1. 柏勳說有知夏留下的資料
2. 她覺得自己欠知夏一個答案
3. 她已經決定今天要辭職，心理上把這次會面當成「離開前最後一件事」

因此玩家可以從不同角度介入。

## 路徑 A｜取得信任

```text
理解攝影作品集
→ 不拿知夏逼她
→ trust >= 2
→ 若晴主動告知 17:20 要去車站
→ 玩家有機會說服她延後
```

## 路徑 B｜解決現實問題

```text
幫若晴處理母親臨時狀況
→ 若晴必須留在家中
→ 無法去車站
```

這條路不需要高 Trust，但若晴不一定理解玩家為什麼阻止她。

---

# 世界線改寫

Baseline：

```text
17:40 柏勳離院
→ 18:05 柏勳把資料交給若晴
→ 18:18 若晴仍在車站
→ 18:31 若晴死亡
```

Chapter 2：

```text
17:20 若晴行程被改變
→ 18:05 柏勳抵達車站，若晴沒出現
→ 柏勳嘗試聯絡若晴，沒有得到即時回覆
→ 柏勳決定自己保留資料並返回醫院
→ 18:24 經過舊維修通道
→ 18:31 因果收束事件發生
→ 柏勳死亡
```

重要：死亡方式不要設計成像另一個普通謀殺。
應讓現場具有「事故」與「異常」雙重解釋，例如：

```text
舊站電力短暫恢復
→ 維修門誤鎖
→ 線路異常放電／設備啟動
→ 柏勳倒下
```

玩家第一眼仍能用現實原因理解。
但與上一輪比較後會發現：

```text
死者變了
時間沒變
局部停電沒變
鐘聲沒變
某個舊設備啟動沒變
```

這些才是 Chapter 2 真正要留下的 Invariant。

# 若晴活下來之後

18:31 之後不要讓若晴只負責哭或提供線索。

她仍然有原本的人生。

## 20:30｜辭職

如果玩家沒有另外干預：

若晴回到咖啡店。

她把早就寫好的辭職信拿出來。
店長其實早就知道她在準備作品集。

對話重點不是煽情，而是讓玩家第一次看到一個被救下來的人繼續往下一件事走。

若晴可以說：

> 我本來以為今天做完那件事，就可以走了。

停一下後再補：

> 結果好像還是得走。

這裡的「走」同時指離開咖啡店、離開灰潮鎮，也讓玩家聯想到知夏。

# 玩家在這章應得到的 Card

## Worldline Card｜若晴存活

```text
18:31
許若晴：存活
位置：非舊車站
```

這張卡本身不是完成條件。

## Event Card｜陳柏勳死亡

```text
18:31
地點：舊車站維修通道
死因：待確認
持有物：林知夏封存醫療資料
```

## Invariant Card｜18:31

第二次比較後才能升級：

```text
Loop 01：許若晴死亡
Loop 02：陳柏勳死亡

相同：
- 18:31
- 車站區域異常
- 短暫停電
- 鐘聲

不同：
- 死者
- 前置人物行程
```

# 延遲後果

## 19:10｜周志遠

柏勳死亡後，志遠第一次主動懷疑這不是單純謀殺。

因為五年前知夏死亡現場也出現相似電力異常。

但他仍不會立刻交出未登錄錄音設備。

## 19:50｜葉庭安

柏勳死亡會讓庭安原本進研究所的計畫改變。

```text
柏勳存活
→ 庭安 19:50 獨自進研究所

柏勳死亡
→ 庭安先去確認醫療資料是否落入警方手上
→ 研究所行程延後
```

玩家救若晴，因此間接改變庭安晚上的行程。
這是第二層延遲影響。

## 20:00｜周予安

如果玩家整天都叫予安幫忙，他會錯過原本和房仲的約。

他嘴上會說沒關係。
但世界線歷史應記錄：

```text
20:00 店面看屋取消
原因：予安不在場
```

讓玩家知道自己不是只改死亡事件。

# Chapter 2 結尾

玩家回看兩條世界線：

```text
Loop 01
若晴 → 18:31 死亡
柏勳 → 存活

Loop 02
若晴 → 存活
柏勳 → 18:31 死亡
```

玩家最重要的推論不是：

> 下一輪要同時救兩個人。

而是開始出現疑問：

> 為什麼一定是 18:31？

姊姊留下的那句話此時第一次真正有意義：

> 如果你看到 18:31 第二次，不要先救第一個死者。

因為知夏早就知道：死者不是核心。

# 對 Event Graph 的最小需求

這一章實作時至少需要下列節點：

```text
wakaharu_tells_station_plan
→ prevent_wakaharu_station
→ doctor_arrives_without_wakaharu
→ doctor_changes_route
→ convergence_1831_doctor
→ wakaharu_resignation_2030
```

以及 delayed effects：

```text
doctor_dead
→ reporter_replans_institute

yuan_busy_with_player
→ realtor_meeting_missed
```

不要直接寫成「若晴被救 → 柏勳死」。
中間必須保留角色做決定的節點，否則 Event Graph 會失去人物感。
