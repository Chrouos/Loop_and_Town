# 第一輪故事｜第一個今天

> 第一輪的目的不是讓玩家破案，而是讓玩家先相信一個非常合理、但其實不完整的因果。
>
> 同時必須讓玩家在死亡發生以前，先看見這些人原本正在過什麼生活。

> Gameplay note：本篇描述 Author Canon 與玩家可能遭遇的場景。
> World Event 不等於 Player Knowledge；跨 Loop 可檢索紀錄仍遵守 `Attention → Perception → optional Memory Capture`。

> Time note：`06:12` 為 Hard Reset checkpoint，`07:20～08:00` 抵達灰潮鎮，`18:31` 為 Causal Convergence，`00:00` Hard Reset。

> Opening canon：主角**本來就已經決定返鄉**。知夏名義寄出的信是警告，不是召喚。信件的精確投遞／跨世界線機制目前仍是 TBD。

---

# 第一輪核心

```text
灰潮鎮地方更新
→ 林家老屋進入必須處理的階段
→ 主角排好返鄉行程、買好車票
→ 出發前收到知夏名義寄出的「不要回來」
→ 06:12 返鄉列車醒來
→ 07:40 抵達灰潮鎮
→ 重新碰到以前的人
→ 發現每個人都對知夏隱瞞了一點事情
→ 若晴原本就會前往舊車站
→ 18:31 若晴死亡
→ 柏勳成為最合理的嫌疑人
→ 發現五年前知夏也死於 18:31
→ 23:59 沒有鐘的鐘樓響起
→ 00:00 Hard Reset
→ 10/3 06:12 第一個今天重新開始
```

第一輪真正留下的問題不是「誰殺了若晴」。

而是：

> 為什麼一個死了五年的人知道我要回來？
>
> 為什麼五年前和今天都指向 18:31？
>
> 剛才發生的今天，為什麼又重新開始？

---

# 第一輪不能提前告訴玩家的事

第一輪不直接解釋：

- 研究系統為什麼重新進入危險狀態
- 主角是否是 Reference / Observer，以及具體機制
- 知夏為什麼能保留五年前 Rewrite 的資訊
- 「不要回來」如何在五年後寄出
- 18:31 完整 Cascade Failure
- 00:00 Hard Reset 的最終停止條件

尤其禁止第一輪直接把信寫成完整操作手冊，例如：

```text
如果午夜鐘響，就代表又失敗了
```

這會過早把知夏已掌握的機制、信件功能與午夜 Reset 綁死。

---

# 06:12｜返鄉列車

主角在列車上醒來。

窗外天色剛亮。

手機顯示：

```text
10 月 3 日
06:12
```

她五年沒有回灰潮鎮。

這趟行程不是臨時決定。

灰潮鎮最近正在進行舊城與地方更新，林家老屋的產權、估價與出售終於不能再拖。

她已經：

```text
和仲介約好
→ 文件排好
→ 車票買好
→ 預計停留幾天
→ 整理完房子就離開
```

她甚至可以把這趟行程理解成：

> 這次回去，就是為了以後不用再回去了。

但是出發前，她收到一封信。

```text
寄件人：林知夏
郵戳：昨天
```

她姊姊已經死了五年。

目前第一輪只固定玩家能明確確認到一個核心訊息：

> **不要回來。**

主角第一反應不是「姊姊復活」。

更合理的解釋包括：

- 惡作劇
- 有人冒用知夏名字
- 一封延遲多年才寄出的舊信
- 某個知道她返鄉行程的人故意嚇她

而且行程已經安排完成。

所以她仍然上車。

信沒有把她召回灰潮鎮。

信只讓原本很單純的返鄉，多了一個她無法忽略的問題。

玩家此時可以閱讀、收起信件、看向窗外或繼續休息。

不管玩家做什麼，列車與世界時間都持續前進。

---

# 07:40｜抵達灰潮鎮

火車停穩時，主角才發現灰潮鎮的月台比記憶裡窄了一點。

周予安站在出口旁。

他沒有像久別重逢的人那樣揮手，只伸手接過她其中一個行李箱。

「比我想的早。」

「車沒誤點。」

「灰潮鎮唯一還算準時的東西。」

主角笑了一下。

這是五年前沒完成的另一個 Moment。

當年她和知夏大吵後，曾傳訊息叫予安不用來送她。

予安最後還是去了，只來得及看見火車離站。

主角不知道這件事。

五年後，他終於真的站在出口接到她。

---

# 07:55｜正在更新的灰潮鎮

離開車站後，玩家應該很早就看到「灰潮鎮正在往前走」。

不是用說明文字，而是環境：

- 道路施工告示
- 舊城更新公告
- 防災／交通設備更新標誌
- 部分舊設施正在拆除或重新接線
- 老街有新的估價、招商或整建通知

這些東西此時只是背景。

玩家不會知道，同一波更新也正在重新碰觸五年前的研究成果。

經過鎮中央時，主角抬頭看見鐘樓。

塔還在。
上半部卻空了一塊。

「鐘呢？」

予安抬頭。

「拆了。」

「什麼時候？」

「妳姊出事那年。」

「為什麼拆？」

「說是結構有問題。後來也沒裝新的。」

第一輪此時不需要再給鐘樓額外解釋。

---

# 08:05｜老家

門鎖比記憶裡更難開。

予安試了兩次，最後用肩膀頂了一下門才鬆開。

清晨的光把灰塵照得很清楚。

桌上或信箱裡可以有此次返鄉真正的現實理由：

- 仲介文件
- 房屋估價資料
- 更新區域通知
- 產權確認文件

主角今天原本最重要的 Main Action，不是查研究所。

而是：

> 整理這間房子。

予安先去把窗戶一扇一扇打開。

整理到一半，他的手機震了一下。

螢幕上是一則房仲訊息。

> 今晚 20:00 還方便看店面嗎？

主角瞥到一眼。

「你要賣店？」

「還沒決定。」

這讓玩家很早知道：

> 不只有主角正在處理「要不要留下過去」。

---

# 08:25｜知夏的房間

房間幾乎保持著五年前的樣子。

書桌附近有三樣容易引起注意的東西：

- 一張知夏與研究人員的舊合照
- 一只停走的手錶
- 一本被撕掉部分頁面的筆記本

手錶停在 **18:31**。

照片裡除了知夏，還有較年輕的葉庭安與研究人員。

筆記本留下大量日期、時間、地點。

「18:31」反覆出現。

但第一輪不能直接替玩家解釋它的重要性。

---

# 08:50～15:30｜世界沒有等待玩家

這段不是「等待傍晚主線開始」。

```text
若晴     08:00 上班
          11:30 整理《退潮以後》作品
          14:00 收到外地攝影相關通知

予安     鐘錶店 / 主角老家之間移動
          20:00 原本有房仲約

庭安     按自己的調查路線準備晚上的研究設施行動

柏勳     正常醫院行程
          17:40 原定秘密離院
```

玩家可能整理老家、外出、休息、觀察施工、錯過某些 Opportunity。

NPC 不會因玩家沒有去找他們就停止生活。

---

# 15:30｜要不要查那封信

予安若實際看到信件，第一反應不是鬼故事。

而是看郵戳。

「這至少可以查。」

主角可以請他去郵局，也可以讓他留下。

這會改變他的 Schedule。

```text
去郵局
→ 得到郵務異常資訊
→ 傍晚不會經過舊車站外圍

留下 / 回店
→ 可能經過舊車站外圍
→ 有機會看到其他人物行蹤
```

這不是派遣 NPC 換獎勵。

而是：

> 做一件事，就代表沒有出現在另一個地方。

---

# 16:10｜許若晴

老街咖啡店。

若晴正在整理幾張攝影作品。

主角只瞥到一張，是清晨還沒開門的商店街。

她的手機亮起外地攝影相關通知，又很快被按掉。

這件事和案件無關。

但對若晴自己可能比案件更重要。

主角提到自己回來整理林家老屋。

若晴明顯停頓。

「林知夏是我姊。」

「我知道。」

「妳認識她？」

「以前在圖書館見過。」

不是完整的回答。

如果玩家把警告信拿給若晴看，她最在意的是：

> 「昨天？」

她盯的是郵戳日期。

玩家如果把 Attention 移開，就可能只聽到部分內容。

---

# 16:40｜葉庭安

主角離開咖啡店後，可能遇到葉庭安。

庭安自稱正在做灰潮鎮人口外流與舊研究設施的調查。

主角若已看過早上的合照，就有材料自己發現：

> 她和知夏的關係不像「只見過幾次」。

庭安今晚本來就有自己的調查路線。

玩家是否當場追問，只改變她後續採取的方法，不創造她的行程。

---

# 17:20｜若晴原本就會去舊車站

若晴今天的行動不能因為主角出現才生成。

她本來就在確認知夏留下的一部分資料。

關係足夠、對話沒有被關閉時，她可能告訴主角：

> 我晚點要去舊車站。
> 陳醫生要把一份以前留下的東西交給我。

即使主角今天沒有返鄉，若晴仍然會去。

主角的出現只會改變：

> 若晴後來要不要讓她一起知道。

---

# 17:40｜陳柏勳離院

Author Truth：

```text
17:40  柏勳離開醫院
17:58  抵達舊車站
18:05  若晴抵達
18:07  柏勳把封存資料交給若晴
```

Player Knowledge 必須靠實際 Perception。

如果玩家沒有看見，就不能因為 Author Timeline 存在而自動知道。

---

# 17:52｜若晴改變「要不要讓主角知道」

如果此前條件成立，若晴可能傳訊息：

> 妳還在鎮上嗎？
>
> 我想了一下。
> 妳還是過來比較好。
>
> 有些東西本來就不是我的。

這不是知夏五年前預知主角一定會在今天回來。

這是**若晴在今天知道主角已返鄉後做出的當輪選擇**。

---

# 18:18｜最後一次正常對話

如果主角實際抵達舊車站，她可能找到拿著封存資料的若晴。

柏勳已經離開視線。

「為什麼陳醫生要給妳？」

若晴可以回答：

> 「這些是知夏姊當年留下來的。」
>
> 「陳醫生一直沒有公開。」
>
> 「她沒有說一定要交給妳。」
>
> 「是我覺得……妳既然真的回來了，至少應該由妳自己決定要不要看。」

這樣避免形成舊版矛盾：

```text
知夏拼命阻止妹妹回來
卻又五年前預先安排「等妹妹回來就交給她」
```

資料中可以存在一句知夏留下的舊標記：

> **18:31 不是死亡時間。**

此句只表示知夏當年已察覺 18:31 不能簡化為「死亡發生時間」。

若晴不知道完整原因。

---

# 18:31｜第一個死亡事件

18:30。

舊車站附近設備出現異常。

18:31。

停電、設備錯誤、金屬撞擊或其他第一輪可感知症狀發生。

具體 Cascade Failure 技術鏈目前仍屬後續 Canon TBD；第一輪不要提前宣告單一「事故核心」。

備援電源恢復時，若晴倒在舊月台附近。

柏勳不在現場。

玩家若真的看見相關行動，可能自己拼出：

```text
17:40  柏勳秘密離院
18:05  柏勳與若晴碰面
18:07  柏勳交付不明資料
18:31  若晴死亡
```

這是一條非常合理的 False Causality。

> 陳柏勳殺了她？

系統不能替玩家確認這個推理。

---

# 19:10｜郵局的異常

如果予安下午去查信，他帶回的只能是行政層面的異常。

目前可以固定：

```text
郵戳日期：昨天
寄件人署名：林知夏
知夏死亡：五年前
```

可以再加入「郵務資料對不上」作為 Mystery，但不得因此在第一輪直接確定 Watchdog、跨線傳輸或任何特定技術解答。

---

# 19:20｜被行程交換掉的情報

如果予安沒有去郵局，他可能在原本路線經過舊車站外圍，看到庭安或其他人物的異常行蹤。

玩家第一次很具體地理解：

> 讓一個人去做一件事，同時會讓另一件事在沒有他的情況下發生。

這是後續 Event Graph / Worldline gameplay 的直覺教學。

---

# 20:00｜予安自己的事

予安原本有自己的房仲約。

如果主角一直要求他陪著處理今天的事情，他可能因此錯過。

這個 Moment 沒有案件答案。

它只讓玩家開始感覺：

> 「為了我的調查改變一個人的行程」本身就是一件有重量的事情。

---

# 20:30｜五年前也是 18:31

周志遠只提供目前程序上能拿出的正式案件摘要。

```text
姓名：林知夏
地點：舊車站周邊
死亡時間：18:31
```

如果玩家真的知道今天若晴死亡時間，才有材料自己並排：

```text
五年前 18:31  林知夏死亡
今天   18:31  許若晴死亡
```

系統不自動宣告：

> 18:31 是 invariant。

---

# 21:14｜庭安走她自己的路

庭安今晚本來就打算調查舊研究設施。

玩家白天是否給她壓力，可能改變她走哪個入口、何時失聯、會看到什麼。

但不要把 Author downstream cause 直接顯示給 Player。

---

# 22:40｜手錶

玩家現在可能第一次真正有理由重新看知夏停在 18:31 的手錶。

若劇情保留「後蓋刻字」設計，必須遵守：

- 字從早上就存在
- 不是劇情需要時才生成
- 不直接解釋 Loop 技術機制
- 不假設文字一定是寫給妹妹

目前可保留的內容：

> 如果你第二次看見 18:31，
> 不要先救第一個死者。

它的作用是製造認知問題：

> 今天明明是我第一次看見，知夏為什麼會寫「第二次」？

---

# 23:20｜一段真正安靜的時間

午夜前需要一段沒有新案件答案的時間。

主角和予安可能坐在老家。

予安問：

「妳這次真的只是回來賣房子？」

主角可以把那封「不要回來」推給他。

「妳收到這個，還是照原本行程回來？」

「房子本來就要處理。」

「妳可以先跟我說。」

「你會信？」

予安想一下。

「不會。」

然後補一句：

「但我會去接妳。」

這段仍然沒有案件答案。

它只建立人與人之間的關係。

---

# 23:59｜沒有鐘的鐘聲

第一聲響起時，主角以為自己聽錯。

鐘樓明明沒有鐘。

第二聲。
第三聲。

玩家此前**沒有從警告信得到「午夜一定會鐘響」的操作說明**。

所以這一刻應該是新的異常，而不是「驗證信件預言」。

世界仍持續向 00:00 前進。

---

# 00:00｜第一次 Hard Reset

第十二聲落下。

00:00。

畫面熄滅。

Canonical transition：

```text
23:59 鐘聲
→ 00:00 Hard Reset
→ World State reset
→ NPC Relationship / previous-loop memory reset
→ 10 月 3 日 06:12
```

再次亮起：

```text
返鄉列車
手機：10 月 3 日 06:12
主角醒來
```

上一輪今天才產生的普通照片、訊息與通話紀錄回到 checkpoint 世界狀態。

主角記得。

玩家主動 Captured 的 Memory / Investigation Wall 依 Core Gameplay 保留。

而那封信仍在外套口袋裡。

但原因非常普通：

> **它在 06:12 checkpoint 之前就已經被主角收到。**

所以它本來就是這個 checkpoint 的 World State。

不需要額外設定：

```text
信件具有特殊物理抗 Reset 能力
```

更不在第一輪自動增加：

> 這是第幾次了？

任何「信件內容會跨 Loop 動態改變」的設定，都必須等信件傳輸機制定案後才能重新加入 Canon。

主角重新攤開信。

內容和幾個小時前一樣。

> **不要回來。**

但這一次，她對這句話的理解已經完全不同。

第一輪結束。

---

# Player-facing memory rule

本章所有 Moment 都遵守：

```text
World Event
→ Attention
→ Perception
→ optional Memory Capture
→ Persistent Memory
```

Author 可以知道哪些事件重要，但 Player UI 不因作者重要度自動建立 Truth / Event / Invariant Card。

玩家也不會因為進入下一輪，自動獲得上一輪沒有看到的完整 Author Timeline。

---

# 第一輪 Canon 檢查

第一輪必須同時成立：

```text
主角返鄉原因 = 老屋 / 自己的人生需求
信 = 警告，不是召喚
地方更新 = 主角返鄉與舊系統重新被碰觸的共同背景
18:31 = Causal Convergence，不直接等於「一定死一人」
若晴 = 原本就有自己的舊車站行程
00:00 = Hard Reset
06:12 = canonical checkpoint
信在 Reset 後存在 = checkpoint 本來就包含它
信件精確投遞 / 跨線功能 = TBD
```
