# Story Canon｜主角返鄉與五年後系統重啟

> Status：Confirmed story direction。
>
> 本文件固定「主角為什麼在五年後回到灰潮鎮」以及「為什麼研究系統也在同一時期重新進入危險狀態」的高層因果。
> 具體 Anchor / Reference Subject 的技術實作、Watchdog 實現方式、18:31 的完整事故鏈仍可後續細化，但不得把主角返鄉本身寫成超自然或命定式的 Loop 開關。

---

# 一句話定位

> 主角不是被 Loop 召回灰潮鎮。
>
> **灰潮鎮正在試圖往前走；同一波更新，一邊要求她回來處理過去，一邊把五年前沒有真正消失的研究系統重新接回現在。**

---

# Canon 1｜主角原本就要回灰潮鎮

主角返鄉的直接原因與 Loop 無關。

五年前知夏死亡後，林家的老屋一直沒有真正處理完。

它可能長期處於：

- 空置
- 基本稅費持續支付
- 家具與知夏遺物大多維持原狀
- 偶爾由熟人協助查看
- 家人一直沒有真正決定出售、保留或整理

五年後，灰潮鎮進入一波舊城與地方更新。

因為住宅重新估價、收購、產權確認或周邊改建，林家的房子終於不能再無限拖延。

因此主角必須本人返鄉處理：

```text
整理遺物
→ 確認房屋狀況
→ 與仲介 / 相關單位處理文件
→ 決定出售
→ 離開灰潮鎮
```

她最初的心理不是「回家」。

更接近：

> **這次回去，就是為了以後不用再回去了。**

---

# Canon 2｜同一波地方更新也碰到了五年前的研究系統

主角返鄉與研究系統重新進入危險狀態，不是兩個毫無關聯的巧合。

它們都來自灰潮鎮正在進行的同一波更新。

```text
灰潮鎮更新 / 再開發
├─ 老街、住宅、產權與土地整理
│  └─ 林家老屋必須處理
│     └─ 主角返鄉
│
└─ 防災、交通與地方基礎設施升級
   └─ 五年前研究計畫留下的模型 / 資料被重新利用
      └─ 原本被隔離的部分系統重新連線
```

這個更新計畫本身不是邪惡行動。

對正在衰退的灰潮鎮而言，它可以有合理甚至必要的目的：

- 改善防災系統
- 更新交通與公共設施
- 整合過去累積的地方資料
- 降低維護成本
- 重新利用曾經投入大量資源建立的研究成果

真正的問題是：

> 五年前只有極少數人知道，那些被標記成「停用」「封存」「舊系統」的東西，為什麼必須保持斷線。

---

# Canon 3｜知夏沒有留下可以重新啟動 Loop 的危險終端

知夏既然已經理解 Reality Write-back 的危險，就不會在老家留下可以讓妹妹誤觸、重新啟動整套系統的完整終端。

五年前她能做到的是：

> **切斷研究 Core 與現實控制層之間的關鍵 Write-back / Synchronization 路徑。**

可以用高層結構理解：

```text
【研究 Core】
Digital Twin
Prediction / Intervention Model
Historical Snapshot
Reference / Observer Records
        │
        X   ← 五年前被切斷
        │
【現實控制層】
電網 / 交通 / 醫療 / 派遣 / 車站等系統
```

知夏無法合理做到的事情包括：

- 刪除研究機構所有主機與備份
- 刪除異地 Disaster Recovery Snapshot
- 銷毀政府或合作單位保存的歷史資料
- 保證未來任何工程人員都不會重新利用舊成果

她不是一個能永久控制整套公共與研究基礎設施的人。

因此她的解法是「讓它停止」，不是「從世界上抹掉它」。

---

# Canon 4｜五年後的重啟不是知夏主動留下的陷阱

五年後，新系統或資料遷移工程重新碰到舊研究成果。

工程端可能只看到：

```text
舊模型
歷史資料
停用的 synchronization service
未完整記載原因的隔離設定
```

在不知道五年前真正事故機制的情況下，重新接入這些資源是一個可以理解的工程決策。

因此：

> **Loop / Reality Rewrite 的危險重新出現，是地方系統重新連線的結果，不是知夏故意把危險留給妹妹。**

---

# Canon 5｜主角返鄉不是 Loop 的充分條件

禁止使用以下因果：

```text
主角踏進灰潮鎮
→ 因為血緣 / 命運 / 世界認出她
→ Loop 自動開始
```

主角不是超自然開關。

目前高層因果應理解為：

```text
舊系統重新連線
+
五年前與 Reality Write-back 有關的 Reference / Observer 條件重新成立
↓
Correction / Rewrite 再次具備執行條件
```

主角與這個 Reference 條件的確有特殊關係，但**具體技術機制仍是 TBD**。

目前只固定：

- 她不是因為「林家血統」而觸發 Loop
- 系統不應愚蠢地把妹妹辨識成「復活的林知夏」
- 若使用 Reference Subject 概念，主角應是五年前事故中真正參與過該閉環的人，而不是五年後臨時被挑中
- Anchor / Reference 只用來解釋跨 Rewrite 的觀測或同步條件，不自帶「必須死亡」規則

---

# Canon 6｜信是在主角已經決定返鄉之後出現

主角不是因為收到信，才突然決定回灰潮鎮。

正確順序是：

```text
老屋進入必須處理的階段
↓
主角與仲介 / 相關人員約好
↓
返鄉行程已確定，甚至車票已買
↓
出發前收到一封信
```

信件：

```text
寄件人：林知夏
郵戳：昨天

內容核心：
「不要回來。」
```

知夏已死亡五年。

因此真正令人不安的不是「死人叫她回家」，而是：

> **一個死了五年的人，似乎知道她正準備回去，而且再次要求她不要回來。**

---

# Canon 7｜為什麼收到「不要回來」仍然返鄉

主角不是因為恐怖片式的好奇心硬闖。

她有已經存在的現實義務：

- 房屋必須處理
- 文件與行程已安排
- 她本來就打算只停留短時間

她的理性解釋首先會是：

```text
惡作劇
有人冒用知夏名字
認識知夏的人刻意嚇她
延遲 / 異常寄出的舊信
```

而且「不要回來」本身會碰到她五年前沒有解開的傷口。

因為知夏死亡前的一段時間，也曾異常強硬地阻止她回灰潮鎮。

主角當年只理解成：

> 姊姊變了。

五年後，同一句話以不可能的方式再次出現。

因此她返鄉同時包含兩層動機：

```text
表層：
處理老屋、完成出售、離開

內層：
確認到底是誰寄信，以及五年前知夏為什麼一直要她離開
```

但故事開場不能把內層動機寫成她早已決定「調查研究所」。

她一開始仍然是在處理自己的生活。

---

# 主題作用

這個設定讓「五年後」不是單純的時間跳躍。

灰潮鎮正在做兩件相反但同源的事情：

```text
為了繼續活下去
→ 清理舊屋、更新城市、重新利用舊技術

但同一個過程
→ 重新碰到五年前沒有真正處理完的因果
```

因此故事不是：

> 過去的詛咒把主角叫回來。

而是：

> **所有人都想把生活往前推，但「往前走」本身重新打開了當年被封住的東西。**

這也與主角形成鏡像：

```text
灰潮鎮：
想更新、想重新開始
→ 卻重新碰到舊系統

主角：
想賣掉老屋、結束過去
→ 卻重新碰到知夏留下的問題
```

# Opening Canon

目前開場應遵循：

```text
主角已決定返鄉處理老屋
↓
收到知夏名義寄出的「不要回來」
↓
仍按原定行程搭上返鄉列車
↓
06:12 在列車上醒來
↓
進入第一個今天
```

因此舊版本若寫成：

```text
知夏的信主動把主角召回灰潮鎮
```

視為 superseded。
