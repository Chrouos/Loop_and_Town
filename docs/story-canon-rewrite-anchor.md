# Story Canon｜Reality Rewrite、Causal Pivot 與 Anchor

> Status：Current approved mechanism direction。
>
> 本文件記錄目前已定案的 Reality Rewrite / Causal Pivot / Anchor 世界觀規則。
>
> 具體工程事故、Synchronizer 的物理原理、警告信投遞方式與 Ending C 最終操作流程仍可後續細化；不得推翻本文件已鎖定的因果方向。
>
> 若舊文件仍把「灰潮鎮五年前事故」寫成 Reality Rewrite 第一次出現的起點，以本文件為準：**Reality Rewrite 在其他 Pilot Site 早已可能成功；灰潮鎮特殊之處是固定 Anchor Bug 被知夏追到真相。**

---

# 一句話定位

世界並不是第一次在灰潮鎮被改寫。

政府原本以為 Reality-coupling 實驗始終沒有真正成功；實際上它早已在多個城市／鄉鎮 Pilot 中持續進行微幅 Reality Correction，只是每次成功後，人的記憶、紀錄與歷史也一起被新 Reality 覆寫，因此研究團隊只看見「模型資料不穩定／預測結果與現實對不上」。

灰潮鎮真正的異常不是第一次 Rewrite，而是：

> **原本應該不斷輪替的 Causal Pivot，因低機率重複命中與系統 Bug 被固定成 Anchor。**

五年前被固定的是林知夏。

五年後被固定的是主角。

---

# 1. 政府專案原本在做什麼

研究不是時間旅行。

它屬於跨地區的 Urban / Disaster Digital Twin 與 decision-support 計畫。

全國不同城市、鄉鎮有不同 Pilot Site，例如：

```text
山區鄉鎮
→ 土石流 / 避難路線

沿海鄉鎮
→ 淹水 / 颱風 / 電網

高齡化地區
→ 醫療 / 救護調度

交通節點
→ 號誌 / 車流 / 大眾運輸

灰潮鎮
→ 多系統整合型 Pilot
```

研究團隊認知中的正常流程：

```text
Reality data
→ Digital Twin
→ Prediction
→ Simulation
→ Intervention recommendation
```

研究目標是降低：

- 傷亡
- 嚴重傷害
- 醫療超載
- 基礎設施失效
- 災害損失
- 緊急應變延遲

它不是邪惡計畫。

每個 Pilot 都有合理的公共政策與地方發展理由。

---

# 2. Reality Write-back 其實早就成功

政府／研究團隊長期以為實驗沒有證明 Reality Write-back 成功。

因為成功本身會破壞證據。

例如：

```text
模型預測：
週五 18:31 會發生重大事故

↓

Reality Correction 成功

↓

新 Reality：
事故沒有發生
```

Rewrite 後：

```text
人的記憶
歷史資料
事故紀錄
感測器資料
行政紀錄
```

都跟著新 Reality 對齊。

因此研究人員看到的是：

```text
模型預測：重大事故
現實：沒有事故

→ False Positive
→ 模型資料似乎不正確
→ 評估結果不穩定
```

真正發生的卻是：

> **不是模型一直預測錯，而是 Reality 被修正成另一個結果。**

因此存在一個核心反差：

> **系統越成功，研究資料反而越像失敗。**

這也是政府一直沒有意識到自己已經取得「修改 Reality」能力的原因之一。

---

# 3. 世界一直存在微幅 Reality Correction

Reality Rewrite 並不是只在故事發生的某一天才開始。

系統可能以：

- 每日
- 每週
- 每月
- 特定風險事件

等不同尺度持續做 Correction。

高層概念：

```text
Current Reality
↓
預測風險
↓
建立多個 Simulation State
↓
選擇模型認為較佳的結果
↓
修改關鍵因果變數
↓
Reality Rewrite
↓
New Reality
```

這裡的「較佳」不是宇宙客觀真理。

它只是系統依照既定 objective function 所判斷的較低成本／較低傷亡狀態。

因此故事不能把它寫成：

> 系統知道真正「最好的人生」。

它只是在最佳化自己能量化的結果。

---

# 4. Reality Rewrite 是局部因果覆寫，不是全宇宙時間倒流

目前鎖定：

```text
Reality State Coupling
=
State Overwrite
+
Bounded Causal Replay
```

也就是系統不是讓整個宇宙倒轉。

它只能改寫被納入 Digital Twin / Prediction Horizon 的有限 Causal State。

Snapshot 也不是單純的地理地圖：

```text
Causal Baseline
├─ 鎮內人口 / 設施狀態
├─ 電網 / 交通 / 醫療
├─ 即將進入的列車與車輛
├─ 預定抵達的人員 / 物資
├─ 已知行程
└─ Prediction Horizon 內會影響該 Pilot 的 Entity
```

因此 Rewrite boundary 更接近：

> **Bounded Operational Causal Graph**

而不是行政區界線。

一個人即使物理上還沒進入灰潮鎮，只要已經進入當日的 Prediction Horizon，仍可能是 Causal Graph 的有效節點。

---

# 5. Author Event Graph 與 System Causal Graph 不同

故事製作用 Event Graph 描述真正發生的因果。

世界內的 Digital Twin 也會建立自己的 Causal Graph。

但兩者不能直接等同：

```text
Author Event Graph
= 真正的故事因果

System Causal Graph
= 系統對 Reality 的模型
```

系統最大的倫理與技術錯誤之一，就是逐漸把：

```text
Model of Reality
```

當成：

```text
Reality itself
```

這也是 Ending C 的核心主題之一。

---

# 6. Causal Pivot｜每次 Correction 都必須改變一個中心變數

Reality Rewrite 不能每次完整暴力重做所有東西。

系統會選擇一個或少數具有高 Causal Influence 的中心變數作為本次 Correction 的主要改動點。

目前將這個位置稱為：

> **Causal Pivot**

概念：

```text
Worldline A
↓
判定結果不佳
↓
計算哪些變數最可能降低風險
↓
選出 Causal Pivot
↓
改變其位置 / 行程 / 決策條件 / 周邊事件
↓
重新演算
↓
Reality Rewrite
```

Pivot Selection 不是完全隨機。

它受 Causal Influence Weight 影響。

例如：

```text
越靠近事故因果核心
越參與關鍵事件
越可能改變後續結果

→ Pivot Weight 越高
```

但高權重只是提高機率。

**它不是命定選中。**

---

# 7. 正常情況下 Pivot 必須輪替

系統正常應避免同一個人連續成為中心變數。

例如：

```text
Correction 01 → Pivot A
Correction 02 → Pivot B
Correction 03 → Pivot C
Correction 04 → Pivot D
```

這是重要的穩定機制。

原因之一是：同一個 entity 如果長期處在 Rewrite 的比較接縫上，可能產生跨 Worldline consistency 問題。

因此正常系統應存在類似：

```text
previous_pivot
→ 下一次 Selection 時降低權重 / 排除
```

的 repeat-prevention 機制。

具體演算法仍可後續設計。

---

# 8. Rewrite Sensitivity｜少數人比較能感知世界被修正

全世界存在極少數對 Reality Rewrite 比較敏感的人。

目前可稱為：

> **Rewrite Sensitivity / Causal Sensitivity**

這不是 Anchor。

也不是超能力者組織或命定血統。

普通人 Rewrite 後：

```text
Reality A
↓ Rewrite
Reality B

→ 幾乎完全接受 Reality B
```

較敏感的人可能留下非常弱的 Causal Echo：

```text
預知夢
Déjà vu
一句不應記得的話
不明原因的恐懼
對某個地點莫名熟悉
「事情好像本來不是這樣」
```

社會通常會將這些現象解讀成：

- 夢
- 錯誤記憶
- 直覺
- Déjà vu
- 巧合

這些人很稀少，但世界各地都可能存在。

是否具有遺傳傾向目前不需要定案。

不得直接寫成「林家血統」。

---

# 9. 曾經成為 Pivot 的 Sensitive Person，Echo 可能更強

目前方向：

```text
普通人
→ Rewrite Echo 極弱

Sensitive Person
→ Rewrite Echo 較明顯

Sensitive Person + 曾成為 Causal Pivot
→ Echo 可能顯著增加
```

因此歷史上某些看似精準的「預知夢」，可能其實是：

> 一個人感知到已被 Rewrite 刪除的 Reality。

但正常情況下 Pivot 會更換。

所以這種 Echo 不會穩定累積成完整跨 Worldline 記憶。

---

# 10. Anchor 不是一種人，而是一個系統 Bug 狀態

核心定義：

> **Anchor = 同一個 Causal Pivot 因 Repeat Bug 被連續使用，最後被錯誤固定成 Persistent Reference。**

因此：

```text
Sensitive Person ≠ Anchor
Causal Pivot ≠ Anchor
```

Anchor 是异常狀態。

正常：

```text
Pivot A
→ Rewrite
→ Pivot B
```

Bug：

```text
Pivot A
→ Rewrite
→ Pivot A again
```

當同一個 Pivot 在連續 Rewrite 中再次被選中，系統可能將：

```text
previous reference
current reference
```

錯誤判斷為同一次 Correction 尚未完成的 Persistent Reference。

形成：

```text
Pivot Repeat
↓
Reference Cache / Consistency Bug
↓
Persistent Reference Lock
↓
Fixed Anchor
```

具體實作名稱仍可調整。

目前鎖定的是因果，不是函式名稱。

---

# 11. 為什麼 Anchor 能完整記得

普通 Pivot 只短暫處在一次 Rewrite 的比較位置。

Fixed Anchor 則被持續當成跨 Rewrite 的 comparison reference。

概念：

```text
Reality A
     ↘
      Anchor
     ↗
Reality B

Reality B
     ↘
      Same Anchor
     ↗
Reality C
```

如果系統每次都把 Anchor 本身也完全覆寫，它會失去跨 Rewrite 的 reference consistency。

因此 Anchor 的部分主觀狀態沒有被正常清除。

結果：

```text
Temporary Pivot
→ fuzzy Causal Echo

Fixed Anchor
→ persistent cross-Rewrite memory
```

所以 Anchor 的「記得」不是天生能力。

更接近：

> **一個被系統 Bug 固定在 Reality 接縫上的人。**

---

# 12. 五年前｜知夏為什麼成為 Anchor

知夏不是被命運選中。

也不是因為血緣、DNA 或「系統認為她是特殊人」。

五年前 18:31 附近，她因為實際參與研究／地方資料／事故相關事件，位在高 Causal Influence 區域。

因此：

```text
事故核心附近
+
知夏本身 Rewrite Sensitivity 較高
+
Causal Influence Weight 高
```

使她被選成 Pivot 的機率增加。

第一次：

```text
Pivot = 林知夏
```

下一次 Correction 本來應該換人。

但因 18:31 附近的 synchronization inconsistency / repeat-prevention failure，加上低機率再次命中：

```text
Pivot = 林知夏 again
```

這不是必然。

是：

```text
高 Causal Weight
+
保護機制失效
+
低機率重複命中
```

疊加後形成 Anchor Lock。

---

# 13. 知夏不是第一個出現異常的人，但她是第一個追到真相的人

其他 Pilot Site 過去可能也留下過：

- 預知夢
- Déjà vu
- 不合現行資料的私人筆記
- 模型與現實異常高／低的一致性
- 研究員覺得「資料以前不是這樣」的片段

但沒有形成可被穩定證明的完整真相。

知夏的特殊之處不是：

> 世界第一次為她出現異常。

而是：

> **她成為 Fixed Anchor 後，第一次有人能持續記住被刪除的 Reality，並把散落在不同 Pilot / 研究資料中的異常一路追到同一個來源。**

---

# 14. 知夏看到的「預知」其實是已經發生過的世界

對其他人而言：

```text
知夏：「等等會發生事故。」

→ 像預知
```

對知夏而言：

```text
Worldline A
事故真的發生
↓
Reality Rewrite
↓
Worldline B
事故尚未發生
↓
知夏仍記得 A
```

所以她不是在看未來。

她是在記得：

> **一個對所有其他人而言已經不存在的過去。**

---

# 15. Anchor 的真正心理代價

Anchor 的代價不應簡化成遊戲數值，例如：

```text
SAN -10
Memory Damage +3
```

真正的代價是：

> **只有她知道那些被世界刪除的死亡真的發生過。**

例如：

```text
Worldline 01
若晴死亡
↓ Rewrite

Worldline 02
若晴活著
柏勳死亡
↓ Rewrite

Worldline 03
柏勳活著
予安死亡
```

其他人只活在目前這個版本。

知夏卻記得全部。

對目前 Reality：

```text
墓碑不存在
事故紀錄不存在
家屬沒有經歷喪親
歷史沒有留下死亡
```

但對知夏而言：

> 那些人真的死過。

這會造成非常深的心理負荷。

她可能記得：

- 某個人死去的樣子
- 某段已不存在的和解
- 某個人曾對她說過的重要話
- 某條 Worldline 中建立過的關係
- 妹妹曾經死亡的結果

而眼前的人完全不知道。

---

# 16. 知夏一開始不是想停止 Rewrite

知夏最初的目標不是：

> 關閉系統。

她真正相信的是：

> **既然 Reality 可以再修正一次，那一定存在一條所有人都活著的 Worldline。**

因此：

```text
若晴死了
→ 再試一次

若晴活了，柏勳死了
→ 再試一次

柏勳活了，予安死了
→ 再試一次

大家活了，妹妹死了
→ 不能接受
→ 再試一次
```

每一次 Retry 對她都有合理理由。

這也是她後來逐漸越界的來源：

```text
我看過你死
↓
我知道這個選擇會發生什麼
↓
如果我什麼都不做，你真的會死
↓
那我還能把選擇留給你嗎？
```

她從：

```text
理解他人
```

逐步走向：

```text
預測他人
→ 安排他人
→ 替他人決定
```

不是因為她突然變壞。

而是她承受了只有 Anchor 才知道的死亡重量。

---

# 17. 五年後｜主角再次成為 Fixed Anchor

五年後不能寫成：

```text
林知夏妹妹
→ 血緣繼承 Anchor
```

目前方向是：

主角本身也屬於少見的 Rewrite-sensitive person。

回到灰潮鎮後，她逐漸成為當日 Causal Graph 中具有高度影響力的節點：

```text
返鄉
→ 接觸知夏舊案
→ 影響予安
→ 影響若晴
→ 接觸庭安 / 柏勳 / 志遠
→ 大量因果開始經過她
→ Causal Influence Weight 上升
```

系統某次 Correction 選中她為 Pivot。

下一輪本應輪替。

但同一類低機率 Bug 再次發生：

```text
Pivot = 主角
↓ Rewrite
Pivot = 主角 again
↓
Persistent Reference Lock
↓
Fixed Anchor
```

因此五年前知夏與五年後主角形成鏡像，但不是命定繼承。

她們只是：

> **都走進了灰潮鎮因果網路的中心，又撞上同一類極低機率錯誤。**

# 18. 06:12｜Last Clean Causal State

目前五年後 Hard Reset 的 checkpoint 鎖定為：

> **10 月 3 日 06:12 = Last Clean Causal State**

它不是五年前保存到今天的 Snapshot。

它是五年後、地方更新使舊系統重新連線後，當天第一次形成完整有效同步時建立的 Baseline。

概念：

```text
05:xx
多個系統陸續連線
資料仍不完整
↓
06:12
第一次形成完整 Valid Sync
↓
建立 Full Causal Snapshot
↓
標記為 Last Trusted / Last Clean State
```

06:12 之後：

```text
Prediction
→ Intervention
→ Reality 開始受到系統輸出影響
```

因此後面的狀態已經可能 self-contaminated，不能再當作完全乾淨的 recovery baseline。

---

# 19. 為什麼主角在列車上仍屬於 06:12 Snapshot

06:12 Snapshot 不是地理行政區快照。

它是 Bounded Operational Causal Graph。

主角當時雖然仍在返鄉列車上，但：

```text
06:12
主角在列車
↓
約 07:20～08:00 抵達灰潮鎮
↓
當天會直接進入灰潮鎮因果網路
```

因此她已經在 Prediction Horizon 內。

Digital Twin 本來就必須處理：

- 即將抵達的人流
- 進鎮列車
- 救護與物流
- 外部輸入

所以她可以被納入 06:12 Causal Baseline，不需要另外使用「血緣 Anchor」解釋。

# 20. 目前的 Hard Reset 高層方向

五年後系統進入異常 Recovery / Correction Mode。

高層流程：

```text
10/3 06:12
Last Clean Causal State
↓
當日 Prediction / Intervention / Correction
↓
18:31 Causal Convergence
↓
Correction 持續失敗 / 不滿足系統條件
↓
23:59 最後階段
↓
00:00 Rollback
↓
載入 Last Clean Causal State
↓
10/3 06:12
```

目前鎖定：

```text
Loop = Recovery Retry
```

不是：

```text
Loop = 世界要求某人死亡
```

也不是：

```text
Loop = Anchor 活著所以世界必須重來
```

死亡與 Reset trigger 必須保持分離。

---

# 21. 18:31 的目前定位

Reality Write-back 的具體工程故障不需要現在寫死到 sensor / timestamp 細節。

目前只鎖：

```text
Digital Twin
↓
Prediction / Simulation
↓
Intervention / Synchronization
↓
Simulation 與 Reality 的 state boundary 失效
↓
Reality State Coupling
```

18:31 是高度因果收束的 Synchronization / Causal Convergence Point。

不是：

- 固定死亡時間
- Reset 本身
- 犧牲儀式
- 宇宙要求一條命

具體工程事故可以等研究紀錄、終端 Log、Event Graph 需要時再細化。

---

# 22. 與 Ending C 的關係

系統、知夏與主角其實都在做同一件事：

```text
看見不滿意的結果
→ 修改一個變數
→ 再試一次
→ 還不完美
→ 再改
```

系統認為：

```text
我有模型
→ 我知道怎樣的結果成本較低
→ Reality 應該被修成那個結果
```

知夏逐漸變成：

```text
我記得所有結果
→ 我知道你會怎麼死
→ 我應該替你安排
```

五年後主角也會面對同樣誘惑。

因此 Ending C 的高層方向維持：

> **停止 autonomous Reality Optimization / Simulation → Reality Write-back 的權限。**

不是找到一條「完美 Worldline」。

不是殺死 Anchor。

不是讓 Anchor 忘記。

不是交換一名犧牲者。
